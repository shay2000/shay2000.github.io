# shay2000 — portfolio

A personal portfolio and writing site built around open-source work. Content is
Markdown; project data is pulled live from the GitHub API and frozen into JSON
at build time, so builds are fast, deterministic, and work offline.

**Stack:** [Astro](https://astro.build) 5 · content collections · zero client
framework · Shiki dual-theme syntax highlighting · no trackers.

---

## What's in here

| Route | What it is |
| --- | --- |
| `/` | Bento hero — live stats, 52-week commit heatmap, language breakdown, latest commits |
| `/projects` | Every repository, filterable by type and language |
| `/projects/<repo>` | Repo detail: editorial notes, full README, language split, commit log |
| `/writing` | Article index, filterable by tag |
| `/writing/<slug>` | Article with table of contents, reading progress, prev/next |
| `/tags` | All tags, from article frontmatter, repo languages, and GitHub topics |
| `/tags/<tag>` | Everything carrying that tag |
| `/about` | Background, toolbox, principles |
| `/rss.xml` | Feed of all articles |
| `/404` | Custom not-found page |

Plus a **⌘K command palette** (or `/`) that searches every project, article, and
tag from a build-time index — instant, and works offline.

## Getting started

```sh
npm install
npm run dev        # http://localhost:4321
```

> **Note on installing in a sandboxed environment.** If `npm install` fails with
> `CODEBUDDY_BROKER_DENY`, the sandbox is blocking npm's extraction step. Use the
> bundled fallback, which unpacks the same tarballs with native `curl`/`tar`:
>
> ```sh
> npm install --package-lock-only   # generate the dependency tree
> node scripts/install-deps.mjs     # download + unpack node_modules
> ```

### Build and preview

```sh
npm run build      # → dist/
npm run preview
```

## Refreshing the GitHub data

Project pages are driven by real repository data, not hand-written copies.

```sh
npm run sync:github              # profile.json + repos.json
node scripts/fetch-readmes.mjs   # READMEs → src/content/readmes/
```

`scripts/fetch-github.mjs` writes three files into `src/data/`:

- **`profile.json`** — user profile, aggregate stats, per-day commit counts, and
  a language breakdown across every repo.
- **`repos.json`** — every public repo with languages, topics, stats, and the
  most recent commits.
- **`readmes.json`** — raw README markdown (superseded by the content
  collection, kept for reference).

`scripts/fetch-readmes.mjs` pulls each README from `raw.githubusercontent.com`
(no API rate limit), rewrites relative image and link paths to absolute GitHub
URLs, and writes them into `src/content/readmes/` with frontmatter — so Astro's
native Markdown pipeline renders them with syntax highlighting.

An unauthenticated GitHub API call is limited to 60 requests per hour; the full
sync uses roughly 44. For repeated runs, export a token:

```sh
GITHUB_TOKEN=ghp_… npm run sync:github
```

## Writing content

### Articles

Add `src/content/articles/my-post.md`:

```md
---
title: "The title"
description: "One sentence, used for cards, meta tags, and RSS."
date: 2026-09-12
tags: ['Swift', 'macOS']
featured: false          # pins to the top of /writing
glyph: '◆'               # card mark
tone: 'ember'            # ember | moss | iris | sky | sand
---

Your Markdown here.
```

### Project notes

Add `src/content/projects/<repo-name>.md`. The `repo` field must match a `name`
in `src/data/repos.json`. Notes render above the README as "Why this exists".

```md
---
repo: "watt-is-it"
tagline: "Short one-liner."
status: "active"         # active | maintained | experimental | archived
stack: ["Swift", "AppKit"]
---

Editorial context for the project.
```

## Design system

Everything lives in `src/styles/global.css` — one file, tokens at the top.

- **Themes.** Warm paper in light mode, deep charcoal in dark. The saved
  preference is applied by a blocking inline script in `<head>`, so there is no
  flash of the wrong theme; system preference wins on a first visit.
- **Type.** Fraunces (display serif) · Inter (body) · JetBrains Mono (labels,
  metadata, code). All self-hosted via Fontsource — no external font requests.
- **Colour.** A single ember accent; everything else is driven by GitHub's real
  language colours, so the palette is generated by the content.
- **Motion.** Pointer-tracked card spotlights, scroll reveals via
  IntersectionObserver, scroll-driven reading progress, and a marquee — all
  disabled under `prefers-reduced-motion`.

To restyle the whole site, change the tokens in `:root`,
`html[data-theme='light']`, and `html[data-theme='dark']`.

## Deploying

The build output is fully static — `dist/` can go anywhere.

**GitHub Pages.** Set `site` in `astro.config.mjs` to the real URL, then:

```sh
npm run build
npx gh-pages -d dist
```

**Netlify / Vercel / Cloudflare Pages.** Build command `npm run build`, publish
directory `dist`.

Before deploying, update `SITE.url` in `src/lib/site.ts` and the `site` value in
`astro.config.mjs` — both feed canonical URLs, the sitemap, and the RSS feed.

### A note on the social preview image

`public/og.svg` is referenced as the Open Graph image. Most social platforms
will not unfurl SVG — export it to `og.png` at 1200×630 and update the
`ogImage` constant in `src/layouts/BaseLayout.astro` for best results.

## Project layout

```
scripts/
  fetch-github.mjs      # GitHub API → src/data/*.json
  fetch-readmes.mjs     # raw READMEs → src/content/readmes/
  install-deps.mjs      # curl/tar fallback installer
src/
  components/           # Header, Footer, CommandPalette, Heatmap, cards…
  content/
    articles/           # your writing
    projects/           # hand-written project notes
    readmes/            # generated — do not edit by hand
  data/                 # generated JSON
  layouts/BaseLayout.astro
  lib/                  # site config, data helpers, tags, search index
  pages/                # routes
  styles/global.css     # the whole design system
```
